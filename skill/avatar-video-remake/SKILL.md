# 数字人视频复刻

可以单独建人、看人物库或换装，也可以从一条视频开始一路完成。运营只需要看图、选名字或描述想法。全程只问当前需要决定的事，已经指定的人、造型、产品或时段直接沿用。默认做一版，交付宫格和提示词即完成。

## 先让运营看见可选的人

先定位含 `avatar-remake.json` 的项目根目录。项目内的 skill 可按脚本自身位置找到根目录；安装到个人 skills 目录后，从运营当前打开的项目向上查找。显式参数 `--project <项目根目录>` 或环境变量 `AVATAR_REMAKE_PROJECT` 优先。找不到时请运营打开克隆的项目文件夹。运行 `python3 <本skill目录>/scripts/studio.py --project <项目根目录> people`（Python 3 + Pillow）。下文简写的 scripts 路径均相对本 skill，实际执行使用明确路径。

配置中的 studio 指向项目内 `workspace/`，其中 `people/` 是已保存的人物，`runs/` 是仅在本地保留的制作任务。产品位于项目内 `assets/products/`。每次展示人物库前，以及保存新人物或造型前，按[共享同步](references/sharing.md)取得远端更新。不要从历史对话猜测现有角色。

- **收到视频**：先确认能读取本轮视频。在工作区的 runs 下建唯一任务目录，保存该视频的本地副本和一份简短的 task.json，记录源文件名、当前待选事项、已选人物/造型 ID、商品或无商品、时段（未定的值留空）。需要等待用户时先更新；收到选择、完成建人或换装时接回同一任务。恢复时读回记录与原片；多个待办无法区分时让运营看源片名选择。
- **人物库为空**：直接说“这是第一次使用。你想让什么样的人出镜？可以用一句话描述长相和气质，也可以发一张人物参考图。选好形象后，我会接着做这条视频。”按[人物与造型](references/people.md)创建。单独建人时省去最后一句。
- **已有数字人**：把所有人物各一张实际头像展示在对话中，编号并标名字，允许回复编号、名字或“新建一个”。选定人后，有多套造型就展示该人物每套的全身正面图，标明“小夏 · 海边休闲装”等名称；仅一套就采用并告诉运营。只为当前展示的编号建立映射。用户已明确指定完整造型时直接使用。图片用绝对路径内嵌展示，人数多可分组排版，不能只给路径、目录或文字名单。
- **“给小夏换装/换发型”**：直接定位小夏并进入[人物与造型](references/people.md)。单独管理人物时无需源视频，完成后展示新造型。复刻途中换装，保存后继续本条视频。
- **人物在片中的位置**：单主角默认替换主角；多人且目标不清时用动作或衣着指明候选，问替换哪一位。保留配角角色与叙事关系。无人出镜时提示原片没有可替换的人，并问运营想让数字人在哪个动作出镜。源片只指导表演、空间和机位；脸、体型、发型与衣服均以选定造型为准，包括动作场景与服装用途不同的情况。

## 决定是否使用产品

看源片中被讲解、演示或推广的对象。健身器械等情境道具不自动算推广商品。用户指定植入产品时按要求处理。

| 源片与指令 | 操作 |
|---|---|
| 平板演示 | 用户指定型号优先，否则采用 T10P 并在任务说明中点名。 |
| 在推其他品类 | 已指定目标型号就直接使用。未指定时运行产品列表，展示型号预览，T10P 排首位；问“这条想换成哪款平板？回复型号，或说‘用默认款 T10P’。”等到选择再执行。沿用源片拍法，把商品动作和口播改为目标型号能支持的内容。 |
| 普通健身、生活等无推广商品 | 默认只换人，跳过商品选择。明确要求植入时使用所指型号，未指定则用 T10P。 |

`python3 scripts/studio.py --project <项目根目录> products` 从配置的 `assets/products/` 实时读取含产品预览的型号文件夹，返回每款的目录和主图绝对路径。“配件”是参考目录。打开所选型号的图片，按需要找正面、背面、配件图；不凭“画板 N”猜视角。选型号只决定商品身份，出镜配件由脚本决定。没有素材或找不到指定型号时说明具体缺项，让运营选择可用型号或提供素材；不偷换成默认款。

产品图能支持颜色、可见结构和展示动作。参数、价格、赠品、库存和效果须有该型号的明确资料或用户确认。可查项目中对应型号的 assets/products/<SKU>/product.yaml；核对 SKU 和实物一致后使用。跨品类时先尝试用可见动作完成同一镜头目的，例如举起音箱展示外形可改为举起平板展示机身；若核心演示必须依赖未知功能，就问一个具体问题。

## 默认直接交付

依[复刻与交付](references/remake.md)分析本条源片、生成并检查一张宫格和一条 Symphony 提示词。用一句话回显“人物 · 造型／产品（如有）／复刻的动作或场景”后直接制作。只有用户要求先审脚本时才展示脚本等待。生成的提示词使用本条源片的语言、情绪和声音安排，人物档案无需设置音色。

完成时在对话中展示宫格，提供提示词文件入口，并用一句话说明在 Symphony 中将宫格用作视觉参考、将整条提示词复制到生成输入框。只有实际入口另支持人物参考图时才补充推荐所选造型图片。将两个成品和选择记录保存在本次任务目录；如有阻塞，说明已经完成的部分以及继续所需的最小输入。

## 团队共享

创建或换装成功后，按[共享同步](references/sharing.md)提交并推送该次新增的人物/造型文件夹。选人前拉取后再读库，运营 A 保存并同步的人物才能出现在运营 B 的列表中。草稿、原视频、宫格、提示词、分析帧、任务记录均写入被忽略的 workspace/runs/。仅批准并保存的四视图和 look.json 进入 workspace/people/。执行 Git 操作前保持当前授权边界；本项目已明确授权将新建人物和造型同步到指定仓库。同步失败保留本地成果，明确告知尚未共享，不声称其他运营已可见。
