# 多运营共享人物库

项目 Git 远端应为团队指定的 tk-avatar-video-remake 仓库。产品在 assets/products/，人物以 UUID 人物目录和 UUID 造型目录分别存储，追加新造型可减少多人同时编辑同一文件的冲突。

## 展示前更新

先在项目根目录检查 git status --short 和 git remote -v，确认远端与当前项目一致。工作区干净时 git pull --ff-only。有本地修改、未推送提交或拉取失败时先检查原因，保留本地成果；不要覆盖其他人的修改。网络或权限问题时可以继续使用本地库，同时简短告知列表尚未更新。有多位同名人物时展示其实际图片、造型及短 ID 供区分。

拉取完成后运行 `studio.py --project <项目根目录> people`（同时刷新本地画廊），或仅运行 `gallery` 刷新项目根目录的 `Avatar Studio.html`。手动执行 Git 拉取不会自动刷新 HTML，需要补做这个步骤；不要把生成的 HTML 当作需要同步的人物素材。

## 保存后发布

1. 确认新文件夹仅含本次批准的四张 PNG 与 look.json，并检查 git status。草稿和任务产物必须仍被忽略。
2. 若有其他暂存文件，保留暂存状态，先告知本次人物尚未共享，请运营处理后续传。无其他暂存文件时，仅 git add 本次人物/造型的确切相对路径，然后 git commit -m "Add avatar look"。不使用 git add .。
3. git push 到当前远端分支。若其他运营先推送导致被拒，确认工作区干净后 git fetch，再 git merge --no-edit 对应远端分支。追加 UUID 目录通常可直接合并；合并成功后再推送。若出现内容冲突，停止并展示涉及的人物或造型，保留双方素材等待处理。合并或重试最多一轮，网络或权限失败保留本地提交并明确“已本地保存，尚未同步”。
4. 仅推送成功才说明“已同步，其他运营更新项目后可选用”。不强制推送，不自动丢弃工作区内容。

产品新增或改图同样只提交对应型号的确切目录。默认把最终人物素材共享到仓库；任务产物仅保存在各自机器的 workspace/runs/。首次克隆无人物时按创建流程引导。
